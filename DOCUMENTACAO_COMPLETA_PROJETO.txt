Atualizado em: 2026-07-02

1. VISAO GERAL

O Bebidas Scan e um aplicativo Android feito em Flutter para escanear bebidas por codigo de barras, consultar informacoes do produto, visualizar detalhes, avaliar, favoritar e registrar precos.

O projeto tem duas partes principais:

1) Backend
   API propria feita em FastAPI, responsavel por usuarios, login, tokens, bebidas, avaliacoes, favoritos, precos e integracao com Open Food Facts.

2) Mobile
   Aplicativo Flutter Android, responsavel pela interface, login/cadastro, modo convidado, scanner de codigo de barras, busca manual, detalhes da bebida, avaliacao e favorito.

Atualmente o backend tambem esta preparado para rodar em Docker junto com um banco PostgreSQL em outro container. Antes disso, durante desenvolvimento local, tambem foi usado SQLite.


2. OBJETIVO DO APP

O objetivo do Bebidas Scan e permitir que uma pessoa:

- abra o app no celular;
- entre com conta, crie conta ou continue como convidado;
- escaneie o codigo de barras de uma bebida;
- busque os dados dessa bebida na API propria;
- caso a bebida nao exista na base local, tentar buscar dados no Open Food Facts;
- visualizar nome, marca, tipo, codigo de barras, ingredientes e imagem;
- avaliar uma bebida com nota, comentario e "compraria novamente";
- favoritar bebidas;
- registrar e consultar precos no backend.

6. ROTAS PRINCIPAIS DA API

Autenticacao:

- POST /auth/registrar
  Cria usuario e retorna access token, refresh token e dados do usuario.

- POST /auth/login
  Faz login com email e senha e retorna access token, refresh token e dados do usuario.

- POST /auth/refresh
  Recebe refresh token e retorna novo access token.

- POST /auth/logout
  Revoga o refresh token informado.

Perfil:

- GET /perfil/me
  Retorna dados do usuario logado.

Bebidas:

- POST /bebidas
  Cria bebida manualmente. Exige usuario logado.

- GET /bebidas/codigo/{codigo_barras}
  Busca bebida por codigo de barras. Primeiro procura no banco local. Se nao encontrar, tenta Open Food Facts.

- GET /bebidas/buscar?q=termo
  Busca bebidas por nome.

Avaliacoes:

- POST /avaliacoes
  Cria ou atualiza avaliacao do usuario para uma bebida.

- GET /avaliacoes/minhas
  Lista avaliacoes do usuario logado.

Favoritos:

- GET /favoritos
  Lista favoritos do usuario logado.

- POST /favoritos/{id_bebida}
  Favorita uma bebida.

- DELETE /favoritos/{id_bebida}
  Remove uma bebida dos favoritos.

Precos:

- POST /precos
  Registra preco de uma bebida.

- GET /precos/bebida/{id_bebida}
  Lista os ultimos precos registrados para uma bebida.


7. AUTENTICACAO E SEGURANCA

O app usa autenticacao por JWT.

Fluxo:

1) Usuario registra ou faz login.
2) Backend retorna:
   - access_token;
   - refresh_token;
   - token_type;
   - usuario.
3) App salva os tokens com Flutter Secure Storage.
4) Em chamadas protegidas, app envia:
   Authorization: Bearer ACCESS_TOKEN
5) Se o access token expirar, o app tenta renovar com /auth/refresh.
6) Se a renovacao falhar, o app limpa os tokens locais.

Senha:

- A senha nunca e salva em texto puro.
- O backend salva apenas senha_hash.
- O hash e feito com pwdlib[argon2].

Refresh token:

- O refresh token em si nao e salvo direto no banco.
- O backend salva o hash SHA-256 do refresh token.
- O token pode ser revogado no logout.

Variaveis importantes:

- JWT_SECRET_KEY
- JWT_ALGORITHM
- ACCESS_TOKEN_EXPIRE_MINUTES
- REFRESH_TOKEN_EXPIRE_DAYS

Observacao:

Nao colocar valores reais de JWT_SECRET_KEY ou senhas dentro de documentacao publica ou repositorio publico.

9. API EXTERNA OPEN FOOD FACTS

O projeto usa a API publica Open Food Facts para tentar buscar dados de bebidas por codigo de barras quando a bebida ainda nao existe no banco local.

Endpoint usado:

https://world.openfoodfacts.org/api/v2/product/{codigo}.json

Fluxo:

1) App envia codigo de barras para:
   GET /bebidas/codigo/{codigo_barras}

2) Backend procura no banco local.

3) Se encontrar, retorna a bebida local.

4) Se nao encontrar, backend chama Open Food Facts.

5) Se Open Food Facts retornar produto valido:
   - backend extrai nome;
   - marca;
   - ingredientes;
   - imagem;
   - categoria/tipo aproximado;
   - codigo de barras.

6) Backend salva a bebida no banco com origem_dados = "open_food_facts".

7) Backend retorna a bebida para o app.

Tratamento de erro:

- Se Open Food Facts estiver fora do ar, der timeout, retornar erro HTTP ou JSON invalido, o backend retorna None internamente.
- Se nenhum produto for encontrado, a API propria responde 404 com "Bebida nao encontrada".

12. SCANNER DE CODIGO DE BARRAS

Historico tecnico:

1) Primeira abordagem:
   Foi usado mobile_scanner.

2) Problema:
   No Galaxy S25 / Android 16, a camera nao abria corretamente ou gerava erro nativo:
   Attempt to invoke virtual method ... on a null object reference

3) Segunda abordagem:
   Troca para camera + google_mlkit_barcode_scanning no Dart com stream de frames.

4) Problema:
   O preview passou a aparecer, mas o processamento de frame bruto gerava erro de conversao InputImage.

5) Terceira abordagem:
   Manter camera para preview e usar takePicture + InputImage.fromFilePath no Dart.

6) Problema:
   O plugin Flutter do ML Kit ainda gerava erro nativo durante processImage.

7) Solucao atual:
   Manter camera no Flutter para preview e foto, mas fazer a leitura no Android nativo em Kotlin usando ML Kit Barcode Scanning diretamente.

Implementacao atual:

- Flutter tira a foto com camera.
- Flutter chama MethodChannel:
  bebidas_scan/native_barcode

- Metodo chamado:
  scanImageFile

- Parametro:
  path da foto temporaria.

- Android nativo:
  MainActivity.kt recebe o caminho da imagem.

- Kotlin cria:
  InputImage.fromFilePath(...)

- Kotlin usa:
  BarcodeScanning.getClient(...)

- Kotlin retorna o primeiro rawValue encontrado.

Formatos suportados:

- EAN-13
- EAN-8
- UPC-A
- UPC-E
- Code 128

Comportamento:

- Se detectar codigo, app busca produto.
- Se nao detectar, mostra:
  Codigo nao detectado. Aproxime, foque melhor e tente novamente.

- Se der erro de camera, mostra mensagem clara.

- A busca manual permanece disponivel como fallback.

16. COMO MOVER O CONTAINER PARA OUTRO COMPUTADOR

Para mover o projeto para outro computador, existem duas abordagens.

Abordagem simples, com internet:

1) Copiar o projeto inteiro.
2) Instalar Docker Desktop no outro computador.
3) Copiar tambem o arquivo .env.docker.
4) Na raiz do projeto, rodar:

docker compose --env-file .env.docker up --build

5) Fazer backup e restauracao do banco se precisar levar dados antigos.

Backup do banco:

docker compose --env-file .env.docker exec db pg_dump -U bebidas_user -d bebidas_scan > bebidas_backup.sql

Restaurar no outro computador:

Get-Content bebidas_backup.sql | docker compose --env-file .env.docker exec -T db psql -U bebidas_user -d bebidas_scan

Abordagem por imagem Docker:

1) Exportar imagem:

docker save -o api-image.tar bebidasscan-api:latest

2) Levar:

- api-image.tar
- docker-compose.yml
- .env.docker
- bebidas_backup.sql

3) No outro computador:

docker load -i api-image.tar

4) Subir banco e restaurar backup.


17. CLOUD, VPN E CLOUDFLARE

Atualmente, se o backend roda no computador, o app depende desse computador ligado.

Opcoes:

1) Rede local

O APK aponta para:

http://IP_DO_COMPUTADOR:8000

Funciona apenas se celular e computador estiverem na mesma rede, ou se houver roteamento adequado.

2) Cloudflare Tunnel

Permite expor a API local por uma URL HTTPS fixa sem abrir porta no roteador.

Fluxo:

APK -> https://api.seudominio.com -> Cloudflare Tunnel -> computador -> Docker -> FastAPI/Postgres

Vantagens:

- URL fixa;
- HTTPS;
- nao precisa IP fixo;
- nao precisa abrir porta no roteador;
- IP residencial nao fica exposto diretamente.

Limites:

- precisa de dominio para uso definitivo;
- computador precisa ficar ligado;
- Docker precisa estar rodando;
- cloudflared precisa estar rodando.

3) VPN tradicional

Exemplos:

- Tailscale;
- WireGuard.

Boa para uso privado, mas ruim para distribuir APK para qualquer pessoa, pois cada celular teria que entrar na VPN.

4) VPS ou cloud

Melhor solucao para producao 24/7.

O mesmo Docker Compose pode rodar em uma VPS.

Exemplos de provedores:

- Hetzner;
- DigitalOcean;
- Hostinger VPS;
- Contabo;
- Render;
- Railway;
- Fly.io.

- APK release usa assinatura release se key.properties existir; caso contrario, usa assinatura debug como fallback.

- A busca de bebidas depende da qualidade dos dados do Open Food Facts quando a bebida nao existe localmente.
- O scanner atual usa botao "Ler codigo"; ainda nao faz leitura automatica continua.
